# 同步逻辑的测试

改 `index.html` 里跟**云同步**有关的任何东西之前和之后，都跑一遍：

```
node tests/run.js
```

全过会打印 `✓ 5 组全过`；**有一条没过，整个命令的退出码就是 1**。
不用装任何东西，Node 自带的功能就够（macOS 上 `node -v` 有输出就能跑）。

## 为什么值得有这么一套

同步出错的方式几乎都**不报错**：数据悄悄少一天、令牌悄悄漏进备份、
每开一次页面悄悄多记一次 commit。等你发现，已经是几周以后，而那几天的记录找不回来了。

所以这里跑的是 **`index.html` 里那段真代码本身** —— 测试台把它从 HTML 里抠出来，
放进一个假的浏览器环境里执行。不是照着逻辑另写一份来测：
另写的那份跟手机上真正在跑的不是同一段代码，测过了也不算数。

配的是一个**假 GitHub**，实现了真接口的关键脾气：base64 编码、`sha` 版本号、
`sha` 对不上就返回 409。所以"两台设备同时写"这种事在这儿是真会发生的，不是演的。

## 五组分别在盯什么

| 文件 | 盯的是 |
|---|---|
| `merge.js` | 两台设备各记各的，合并之后一条都不少；**令牌不许出现在同步上去的任何东西里** |
| `emptyday.js` | 只是"打开看了一眼"的设备，不许把另一台真记的那天抹掉（见下） |
| `edge.js` | 离线一周回来 · 写冲突要能自己重试 · 坏令牌要老实说 · 断网不丢数据 · 没改过就不写 |
| `connect.js` | 第一次连接要把**所有年份**都推上去 · 新设备能全拉下来 · 记一笔会自动推 |
| `artifact.js` | claude.ai 里的那一版必须**一次外部请求都不发**（平台会挡，发了也是死的） |

### `emptyday.js` 是从一个真事故来的，别删

2026-09-14：页面每打开一次，`render()` 里的 `mk(cur)` 就会给当天建一个**空格子**。
它被同步上去之后，另一台设备会把它当成"我这天有记录"，于是按时间戳去抢 ——
只要那台设备后来在别的日子记过东西，它就会拿这个空格子
**把对方真记的那顿抹掉**，而且一声不吭。

修法是两头都堵（搜代码里的 `emptyDay`）：空的不往上推，也不拿空的去盖别人的。
里面还有一条容易顺手写错的：**判空只能对「对象」生效** ——
体重存的是数字，而 `Object.keys(5.02)` 也是空的，漏了类型判断会把所有体重一起删掉。

## 里面的"今天"是钉死的（2026-09-15 补的）

测试跑的时候，页面看到的"今天"固定是 **2026-09-14**，不是真实日期。

为什么要这样：页面每打开一次，就会给当天建一个**空格子**。所以"一共几天"
这种断言会跟着真实日历变 —— 2026-09-14 写的测试，第二天就红了，
**而代码一个字没改**。跟代码无关却会红的闸，人看两次就开始无视它，比没有还坏。

只冻结 `new Date()`（决定"今天"），**不动 `Date.now()`** —— 那个是时间戳，
合并要靠它比"谁更新"，冻了会全变成平局，反而把真正要测的东西测没了。

顺带把断言从"数个数"改成"查具体哪几天、内容对不对"，两头都堵上。

想验它真的跟日历无关：

```
CATFEED_TEST_TODAY=2028-02-29 node tests/run.js
```

十个日子（跨年、闰年都试过）都是绿的。加新断言时**别再数总数** ——
要么点名查哪几天，要么把"今天"那个空格子排除掉。

## 怎么确认这套闸本身还有效

一套只会打勾、其实什么都拦不住的测试，比没有更坏 —— 它让人放心。
所以每隔一阵子，**故意把代码改坏一处，确认它真的变红**：

```
# 例：把空格子的过滤拿掉，再跑
#   index.html 里 if(yr(d)===y&&!emptyDay(D[sec][d]))  →  if(yr(d)===y)
node tests/run.js      # 应该打印 ✗ 没过：emptyday，退出码 1
```

改完记得改回来（`git checkout index.html`）。

## 想加一条检查

在对应文件里用 `ok("这条在测什么", 条件, "出错时想看到的东西")`，
末尾的 `done(...)` 会自动汇总并决定退出码。造测试数据只用**一眼假**的值 ——
文件里那个 `github_pat_TESTONLY_000` 就是，永远不要贴真令牌进来。
